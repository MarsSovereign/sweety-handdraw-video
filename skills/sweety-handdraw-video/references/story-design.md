# 创作与分镜

新主题先产出 `design.json`，至少包含：

- `narrative_route`：模型判断默认生活问题路线是否适用，写出 decision、reason、director_review；非默认路线增加 director_plan。
- `topic`、`audience`、`explanation_goal`：观众看完能理解或做出的具体事情。
- `source_scope`：原创主题、用户文章、外部文章改编；来源链接和事实依据。
- `visual_direction`：人物设定、用色理由、线条/材质、场景与镜头密度。
- `beats`：每段口播、画面中的具体对象、动作、文字、强调位置以及与口播的对应关系。
- `cover`：准确短标题、主视觉和与正文的一致性。
- `asset_prompts`：生成要求、角色参考职责、是否包含文字、图像来源记录。

这些字段记录设计判断，不是要求所有主题使用相同叙事。生活观点可以用具体困境引入；解释机制可以用对照或操作过程；故事保留人物行动与因果；文章改编不能任意删掉条件以换取戏剧性。

**用户给了稿子，就改错不改意。** 只修事实错误、读不顺的句子和口播里听不清的书面语；作者的观点、取舍、举例和有意的简化（科普里“粗略地说”不是错误）都保留。篇幅增长不超过约20%，用户要求扩写时除外。每处实质改动写进 `design.json` 的 `script_changes`（原句、新句、理由），交付时告诉用户改了哪里。

## 分镜：先算预算，再生图

长片里模型容易偷懒：素材变少、关键画面被跳过、同一张图连用、每镜都是“口播配一幅慢慢画的图”。分镜因此写成 `storyboard.json`，数量和时间全部由脚本按真实旁白计算，不由模型估算。

1. 主题 → 完整口播稿 → 锁定整篇旁白与时间戳（[连续旁白约定](continuous-narration.md)）。语义可先规划，镜头时间必须在声音锁定后定。
2. 导演设计镜头：每个镜头覆盖连续的 beat，为每句先想几种画法，只留最有表现力的一种；`purpose` 写清这一镜比直接念出这句话多解释了什么。
3. 拆出每个镜头需要的视觉元素 `visuals`。
4. 运行 `python3 scripts/storyboard_lint.py JOB --budget`。脚本给出需要的视觉数 `ceil(旁白秒数 / max_hold)`、每个视觉可用的绘制秒数和复杂度档位；数量不够时报错并列出最稀疏的镜头，从那里补视觉。
5. 把每个视觉的秒数和档位写进本图美术简报，再写 drawing-plan（含 `identity_cues`）并生图。图按可用时间设计，而不是画完再压缩时间。
6. 写 `job.json`：动作带 `"visual"`；一个镜头通常对应一个跨句的 `visual_group`，`from_beat` 让后一个元素在它那句开始时起笔。
7. 用 `storyboard_lint.py JOB` 和 `plan_status.py JOB` 查剩余工作；`build` 按实际时间线重算并硬性拦截。

```json
{
  "version": 1,
  "max_hold_seconds": 8,
  "characters": [{"id": "fox", "reference": "inputs/characters/fox.png", "sha256": "参考图实际哈希"}],
  "shots": [
    {"id": "s01", "beats": ["opening", "why"], "type": "scene_with_background",
     "purpose": "雨夜街口让观众先看到困境，再听解释",
     "visuals": [
       {"id": "v01", "kind": "illustration", "subject": "雨夜街口躲雨的小狐狸", "background": "路灯、湿地面", "characters": ["fox"], "weight": 3},
       {"id": "v02", "kind": "text_group", "subject": "两个关键词"}
     ]},
    {"id": "s02", "beats": ["back"], "type": "overview_recap", "callback": "回到开场画面收束",
     "visuals": [{"id": "v09", "kind": "illustration", "subject": "开场狐狸"}, {"id": "v10", "kind": "diagram", "subject": "前后对照箭头"}]}
  ]
}
```

- `shots` 按顺序覆盖全部 beat，每个只出现一次。`kind`：`illustration`、`diagram`（马克笔框线/箭头加文字）、`text_group`。`weight` 同动作权重，只影响预算分配。可选 `source` 记录计划的图片路径，供 `plan_status` 判断是否已生成。
- `type` 及其最低结构：`scene_with_background`（插画声明 background）、`comparison`（≥2 幅插画/图解）、`process_sequence`（≥2 个视觉）、`closeup`（插画）、`key_points`（text_group）、`overview_recap`（≥2 个视觉）、`character_action`（插画中出现已声明角色）。脚本只核对结构，镜头是否真的成立由导演判断。
- `max_hold_seconds` 默认8，可设5–12。`text_only_reason`、`callback` 只在确有理由时填写。

## 脚本计算的预算与门槛

| 检查 | 规则（脚本计算） |
|---|---|
| 视觉节奏 | 每 max_hold 秒内必须有新元素开始绘制；声明 background 的场景图，每个语义部位开始描线也算新元素；报告最长静止段 |
| 复用 | 同一张图（source+crop）连续作为主视觉不超过2个 beat，除非该镜头写 `callback` 理由 |
| 数量 | 视觉数 ≥ ceil(旁白秒数/max_hold)，其中插画/图解 ≥ 80% |
| 构图多样 | 旁白超过45秒：至少3种镜头类型，任一类型 ≤ 60% 时长 |
| 计划即承诺 | storyboard 中每个视觉都必须被 job.json 绘制；job 中每幅插画都必须在 storyboard 中 |
| 纯文字 | 无插画/图解的镜头 ≤ 20% 时长，否则须写 `text_only_reason` |
| 角色一致 | 声明的角色有锁定哈希的参考图；出现该角色的插画，其 drawing-plan 的 `references` 引用该图 |
| 绘制时间 | build 读取引擎 drawability：窗口 < minimum_seconds 报错；短于视频节奏（插画 max(minimum, required/3)）记录警告 |
| 画完要停 | 插画按约3倍人速画完就停，文字按自然速度的1/1.8写完就停，窗口余下的时间留给观看，不放慢去填满窗口；全片笔在画的时间不超过旁白的70%，超过即报错 |

复杂度档位按可用秒数的70%（其余留给观看）、实测约每秒3.5笔（含抬笔与上色）计算：<3秒 只放标签或极小图标（≤10笔）；3–6秒 简单图标/剪影（≤20笔）、平涂；6秒到 max_hold 单一主体（≤28笔）、平涂无纹理线；超过 max_hold 做带背景的场景（声明 background，用部位推进画面）或拆成两个视觉，笔数仍按每秒3.5笔封顶。参考：48笔的南瓜最短约13秒，45笔的葡萄约11秒。窗口不够时，简化图，或用 visual_group 跨句延长窗口；不能截短呼吸、拉慢旁白。

宿主无法生成图片时停止并告诉用户，不能静默降级成只有文字的视频。

## 画面如何服务讲解

每幅图必须回答“它比直接显示这句话多解释了什么”。涉及成本，可以画已经消耗的东西与接下来的选择；涉及时间，可以表现同一人物的先后动作。不要仅靠人物站在纸张、灯泡、箭头旁边代表所有抽象概念。部分镜头应带场景和背景，不要每镜都是白底单物体。

标题和短标签承担导航，口播承担完整论述。避免正文把整段字幕再抄一次。页面可以累积多个相关元素，待一个完整意思讲完再转场；图文位置、数量和比例应随内容变化。

**列举、分类、对比用一块板累积。** 讲“几类工具”“三个步骤”“前后对照”时，先画框架（分栏、流程线、坐标），每句在固定位置补一个小图或标签，讲完一整组才转场；回顾时回到这块板圈出重点，而不是重画。每句换一页、重画一幅满版大图，笔几乎一直在画，观众刚看清就被翻走，也会触发上面的70%门槛。

**一眼认得出。** 主体按观众认识它的方式画：葡萄靠一串果和藤叶被认出，一颗放大的烂葡萄会被看成无花果或李子。drawing-plan 的每个 subject 写 `identity_cues`；出图后运行 `python3 scripts/drawing_contract.py JOB --thumbnails`，看编号缩略图（160px、无字幕），1秒内叫不出名字就重画，结论写进 drawing-review 的 `recognizability`。同时看有没有两格读起来是同一幅画（同一图集里换了裁切的相似小图也算）：脚本只能拦同图同裁切的连用，这种重复要模型自己发现，换图或给后一个镜头写 `callback` 理由。

## 生成素材

先完成[画风选择与可绘制约定](style-and-drawing.md)，任何历史案例的画风都不作为新片默认值。

每张图都先读取随包 sweety-image-art-direction 并写本图美术简报，库内模式保留手绘风格的完整配方；独立推理、自定义模式使用已记录的独立风格说明。简报、最终提示词、清理后哈希和实际查看结论一一对应。

人物和道具在出图前就要考虑能否分部位独立描线。设计阶段列出部位顺序和预计笔划复杂度，不能等画完才发现无法分解。模型查看成图后标注实际部位多边形；通常上到下、左到右，例外须在设计里解释。全部轮廓完成后才填色。

先确定一张本片的身份与画风参考，锁定为 storyboard 的 `characters`，再按场景变化动作和道具。人物服装、脸型与线条保持可辨认的一致性。颜色可以围绕主题重新选，不默认复用梨黄叶绿或任何历史人物。

插画适合干净白底或透明背景、可分辨的轮廓与局部色块。密集照片纹理、极细碎线条会放大路径数量和绘制速度问题；需要这种画风时先做代表段，不先批量生成整套。

正文可控文字由运行工具书写；封面AI只生成主视觉和留白，准确标题必须用可核对、可编辑文字图层合成。生成图片中的无用伪文字、相邻图集残片、异常肢体不能靠“渲染成功”跳过。

## 有效的短段验证

选择包含完整小意思的一段，而不是仅能证明编码成功的几秒静帧。应看到标题底纹逐渐出现、文字写入、插画轮廓、至少一处颜色跟笔尖变化，以及绘制完成后的阅读停留。若固定笔手的袖子裁切边进入画面，重新设计手臂素材或镜头，不能把裁切边当正常效果。

长片按章节推进：每完成一组镜头运行 `plan_status.py`，按 `next_shot` 继续，不要一次生成全部再回头补。
